假设我们有一台服务器，它可以承担 1 百万/秒的请求（100 万 QPS），现在有两个数据请求，商品访问数据 90 万 QPS，订单访问数据 80 万 QPS，很显然服务器 hold 不住了，会各种拒绝访问，甚至崩溃，宕机。解决问题的办法就是加服务器，1 台服务器解决不了就用 2 台，2 台解决不了就用更多的服务器。那如何将流量分摊到多台服务器上呢？如果我们项目拆分成订单服务和商品服务两个独立的服务，分别部署在两台不同的服务器上，就可以解决上述问题。

分布式架构是指将系统部署在多台独立的计算机（节点）上，这些节点通过网络互相通信和协作，共同对外提供服务。通过对系统进行水平扩展或功能拆分，将不同的模块部署到不同的节点上，从而应对高并发和海量数据的挑战。

分布式系统由多台独立的计算机组成，通过网络互相通信和协作，共同完成一个或多个目标。这些计算机可以分布在不同的地理位置，强调资源的分散和共享。分布式系统中的各个节点可以独立运行，并通过消息传递或远程过程调用等方式进行通信。

**架构示意图说明：**
- 客户端发起 http 请求，访问多台 Tomcat 服务器。
- 系统按业务功能拆分为多个独立的子系统，分别部署在不同的 Tomcat 上：
  - 商品系统：连接独立数据库。
  - 购物车系统：连接独立数据库。
  - 订单系统：连接独立数据库。
- 各系统最终响应前端页面（包含商品展示、商品销售、订单管理等模块）。
- 子系统之间通过 RPC（远程过程调用）进行内部通信协作，例如购物车系统通过 RPC 调用订单系统的服务。

2、分布式架构的特点

（1）独立部署：分布式系统中的节点可以独立运行，并通过网络进行通信和协作。节点之间的通信可以通过消息传递、远程过程调用等方式实现。

（2）独立运行：分布式系统可以通过增加更多的节点（垂直扩展）来应对用户量的增长，并且单个节点的故障不会影响整个系统的运行。

3、远程过程调用

RPC（Remote Procedure Call，远程过程调用）是一种分布式计算中的通信方式，用于实现不同计算机之间的程序调用。它允许在一台计算机上运行的程序能够调用另一台计算机上的程序，就像调用本地程序一样简单。RPC 隐藏了网络通信的复杂性，使得分布式系统开发变得更加简单和透明。

也就是说两台服务器 A，B，一个应用部署在 A 服务器上，想要调用 B 服务器上应用提供的方法，由于不在一个内存空间，不能直接调用，需要通过网路来表达调用的语义和传达调用的数据。

4、消息传递

为了提高系统的并发处理能力，大型网站通常采用异步通信的方式。通过引入消息队列和异步任务处理，可以实现任务的异步执行，提高系统的响应速度和吞吐量。消息传递是一种基于消息的发布/订阅模型，一个程序（发布者）将消息发布到一个或多个消息队列或主题上，另一个程序（订阅者）订阅一个或多个消息队列或主题，从主题中接收消息，并处理它们。

**同步处理与异步处理流程对比说明：**

- **同步处理流程：**
  - 1. 填写注册信息
  - 2. 注册信息写入数据库
  - 3. 调用发送短信接口
  - 4. 发送短信（用户等待大约 3 秒）
  - 5. 页面响应注册成功

- **异步处理流程：**
  - 1. 填写注册信息
  - 2. 注册信息写入数据库
  - 3. 发送短信的请求写入消息队列（MQ 消息队列）
  - 4. 页面响应注册成功（无需等待短信发送）
  - 后台从消息队列中取出请求，异步发送短信。

在分布式系统中，远程调用和消息传递是两种常用的通信方式。它们具有各自的特点和适用场景：

- 远程调用适用于需要同步调用远程过程并获取结果的场景，如分布式数据库查询、远程服务调用等。
- 消息传递适用于需要异步通信、解耦或高灵活性的场景，如实时通知、事件驱动系统等。

💡 **速记**

**【为什么需要分布式？】**
单机遇到高并发瓶颈（如 QPS 超百万）-> 垂直扩展有上限 -> 必须进行水平扩展（加机器）和功能拆分（微服务）。

**【分布式核心特点】**
1. **独立部署**：节点通过网络通信协作（消息传递、RPC）。
2. **独立运行（高可用/可扩展）**：增加节点提升性能；单点故障不影响整体系统。

**【两大通信方式对比】**
*   **RPC（远程过程调用）**
    *   **原理**：像调用本地方法一样调用远程。隐藏网络通信复杂性。跨内存空间，需网络传输。
    *   **场景**：同步调用，需要立即获取结果（如分布式数据库查询）。
*   **消息传递（MQ）**
    *   **原理**：发布/订阅模型（发布者 -> 队列/主题 -> 订阅者）。
    *   **场景**：异步通信、解耦、削峰填谷、高灵活性。

**【经典业务场景（同步 vs 异步）】**
*   **同步**（用户注册+发短信）：注册写库 -> 调短信接口 -> 发送短信（等3秒） -> 响应成功。（缺点：用户体验差，吞吐量低）
*   **异步**（优化后）：注册写库 -> 请求写入MQ -> 直接响应成功。（后台异步消费MQ发短信。优点：响应快，系统解耦）
