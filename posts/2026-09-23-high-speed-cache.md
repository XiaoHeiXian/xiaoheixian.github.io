1、高并发的处理方案

高并发场景广泛应用于热门网站、电商平台、社交媒体等互联网应用中。例如，在电商平台上有大量用户同时浏览、搜索商品，提交订单等操作；社交媒体平台上有大量用户同时发布、点赞、评论等操作。这些场景需要系统能够同时处理大量请求，这些请求几乎同时到达系统，需要在短时间内进行处理和响应。由于大量请求同时到达，系统的资源（如 CPU、内存、网络带宽等）可能会面临竞争而资源耗尽，造成系统崩溃。如何应对这些高并发的请求呢？

- 缓存：缓解系统负载压力，提高系统响应速度。
- 限流：控制并发访问量，保护系统免受载影响。
- 降级：保证核心功能的稳定性，舍弃非关键业务或简化处理。

2、缓存

缓存的工作原理是先先从缓存中获取数据，如果有数据则直接返回给用户，如果没有数据则从慢速设备上（MySQL 数据库）读取实际数据并且将数据放入缓存。

**架构示意图说明：**
- 客户端请求先访问缓存数据库。
- 缓存未命中时，再向底层数据库（MySQL）读取数据。

3、常用的缓存方案

（1）反向代理缓存

反向代理缓存是指在反向代理服务器上对请求的响应进行缓存，以提高服务的性能和用户体验。它将经常请求的静态内容缓存在代理服务器上，当有用户请求同样的内容时，代理服务器会直接返回缓存的响应，而无需再次向源服务器请求。

反向代理缓存适用于访问外部服务速度比较慢，但是数据变化不频繁的场景。

反向代理缓存常用的工具：
- Nginx：一款高性能的反向代理服务器，支持反向代理缓存功能，可通过配置文件进行缓存策略的设置。Nginx 代理层缓存主要以 Http 模块与 proxy_cache 模块进行配置即可。
- Varnish：一个专门用于反向代理缓存的开源软件，可以高效地缓存并提供快速的响应。
- Squid：一款功能强大的缓存代理服务器，支持反向代理缓存和正向代理缓存。

（2）分布式缓存

分布式缓存是将缓存数据分散存储在多台服务器上的缓存解决方案。适应于高并发读取、数据共享和协同处理、提供弹性和可扩展性、降低后端请求次数等场景。

分布式缓存常用工具：
- Redis：Redis 是一种高性能的键值存储系统，支持丰富的数据类型和灵活的缓存策略。可以使用 Redis 搭建分布式缓存集群，利用其快速的读写能力和一致性哈希算法实现数据分片和负载均衡。
- Memcached：Memcached 是一种简单而快速的分布式内存对象缓存系统，用于减轻数据库负载和加速动态 Web 应用程序。它采用分布哈希算法进行数据分片和分布式存储。
- Hazelcast：Hazelcast 是一个开源的分布式内存数据网格平台，提供分布式缓存和分布式计算能力。它可以用于构建高吞吐量和高可用性的分布式缓存系统。

（3）本地缓存（进程内缓存）

本地缓存是将数据缓存在应用进程的内存中，访问速度最快（微秒级），适用于数据量小、变更频率低的热点数据（如系统配置、字典数据、商品分类等）。

常用工具：
- Caffeine：高性能 Java 本地缓存库，提供了近乎最佳的命中率，支持自动加载、异步刷新、淘汰策略等特性，是 Spring Boot 默认的本地缓存实现。
- Guava Cache：Google 提供的缓存工具，功能完善，适合中小规模场景。
- Ehcache：老牌 Java 缓存框架，支持磁盘持久化。

4、缓存架构

在实际系统中，缓存通常是多级部署的：

（1）客户端缓存（浏览器缓存）：最靠近用户，减少服务器压力
（2）CDN 缓存：加速静态资源访问
（3）反向代理缓存（Nginx）：缓存热点页面
（4）本地缓存（Caffeine）：缓存应用级热点数据
（5）分布式缓存（Redis）：跨服务共享缓存数据，作为最终缓存层

💡 **速记**

**【高并发三把斧】**
缓存（提升读性能）、限流（保护系统）、降级（保核心舍非核心）。

**【缓存核心原理】**
先查缓存，命中则返回；未命中则查数据库，并将结果回写缓存。

**【常用缓存方案对比】**
1. **反向代理缓存**：Nginx、Varnish、Squid。缓存静态内容/热点页面，适用于数据变化不频繁的场景。
2. **分布式缓存**：Redis、Memcached、Hazelcast。解决高并发读取、数据共享、弹性扩展问题。
3. **本地缓存（进程内）**：Caffeine、Guava、Ehcache。微秒级访问，适用于小数据量、低变更的热点数据（Spring Boot 默认 Caffeine）。

**【多级缓存架构（请求依次向上查询，命中即返回）】**
1. 客户端缓存（浏览器）
2. CDN 缓存（静态资源）
3. 反向代理缓存（Nginx，热点页面）
4. 本地缓存（Caffeine，应用级热点）
5. 分布式缓存（Redis，跨服务共享，最终防线）

**【缓存架构核心思想】**
逐级降低后端压力，越靠近用户的缓存访问速度越快，但容量越小、一致性维护越难。
