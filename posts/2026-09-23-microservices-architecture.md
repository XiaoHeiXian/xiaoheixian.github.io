1、面向服务架构

SOA（Service-Oriented Architecture）即面向服务的架构，是一种软件设计方法，旨在通过定义可复用的服务来促进不同系统间的互操作。SOA 的核心思想是将应用程序的不同功能单元（服务）进行拆分，并通过定义好的接口和协议将这些服务相互连接起来，实现松耦合、高度灵活、可复用的系统。SOA 具有以下特点：

- 松耦合：服务之间通过简单的接口进行通信，不直接依赖彼此的实现，降低了系统之间的依赖关系。
- 服务复用：每个服务都是一个独立的功能单元，可以被多个应用和系统调用和复用，提高了功能的复用率。
- 标准化接口：服务通常使用标准协议（如 HTTP、SOAP、REST）进行通信，确保跨平台和跨语言的兼容性。
- 自治性：每个服务拥有自己的数据和逻辑，能够自主处理请求，降低了对其他服务的依赖。
- 可组合性：服务可以按照需求组合成新的服务或业务流程，通过编排和合成实现复杂的业务功能。

2、微服务架构

微服务架构可以视为 SOA 的一种演进。微服务将每个功能模块拆分成高度自治、独立的服务单元，服务单元更加小型化、独立化，具备独立的数据库和部署流程。与 SOA 相比，微服务架构的服务单元更加细粒度，更加注重服务的独立性和自治性。

微服务架构集成了数据中台思想和分布式集群的特点，是一种将单一应用程序拆分成一组小型服务的架构风格。每个服务运行在自己的进程中，服务间通过轻量级通信机制（如 HTTP API）进行交互。主要用于解决系统复杂度问题，通过将系统拆分成多个独立的服务，每个服务负责一个具体的业务功能，从而降低系统的耦合度，提高开发效率和系统的敏捷性。

**微服务架构示意图说明：**
- 外部请求（商品展示、商品销售、订单管理）统一接入网关。
- 网关通过服务注册和发现中心（接口地址）找到目标服务。
- 服务实例向注册中心进行注册，网关进行服务发现。
- 网关将请求路由到对应的微服务（商品服务、购物车服务、订单服务）。
- 各微服务之间通过 RESTAPI 或 gRPC 调用进行通信。
- 每个微服务拥有自己独立的数据库（DB）。

3、微服务的组成

（1）服务注册与发现：服务注册中心负责存储微服务实例的信息，服务发现则允许其他服务通过查询注册中心来找到并调用目标服务。这是实现微服务间动态通信的基础。

（2）网关：作为微服务的入口点，所有外部请求都通过 API 网关进行转发。它提供统一的入口管理和路由功能，确保请求被正确地路由到相应的服务。

（3）服务：核心服务的集合，每个服务负责特定的业务逻辑，独立部署并完成独立业务功能。以 RESTful API 或消息传递等方式对外提供服务。

（4）分布式缓存：使用缓存系统加速数据读取，减少数据库压力，提升系统性能。

（5）负载均衡器：将请求均匀分配到多个服务实例，确保高可用性和负载均衡。

（6）配置中心：管理各个服务的配置信息，包括环境配置、应用配置、数据库配置等。

（7）权限控制：负责用户身份验证和访问授权，确保只有授权用户才能访问特定的服务或数据。

4、微服务架构的特点

（1）单一职责原则：每个服务只负责一个明确的业务功能，避免功能重叠和复杂性。

（2）服务自治：每个服务独立运行，拥有自己的数据库和代码库，可以独立部署和扩展。

（3）领域驱动设计（DDD）：基于业务领域的复杂性进行服务拆分，确保每个服务都有明确的业务边界。

（4）API 优先：通过定义清晰的 API 接口，确保服务之间的通信规范和一致性。

（5）持续交付和部署：利用自动化工具实现快速交付和部署，提高开发效率和系统稳定性。

【总结】软件架构技术演进对比表：

| 架构类型 | 核心特点 | 适用场景 | 典型问题 |
| :--- | :--- | :--- | :--- |
| 单体架构 | 单一部署单元 | 小规模项目、创业初期 | 扩展性差、部署困难 |
| 分布式架构 | 功能拆分、独立部署 | 中大规模系统 | 运维复杂、网络开销 |
| 集群架构 | 多实例部署 | 高可用要求 | 状态同步、负载均衡 |
| 微服务架构 | 服务自治、独立演进 | 大型复杂系统 | 分布式事务、服务治理 |

💡 **速记**

**【SOA vs 微服务】**
*   **SOA**：企业级、粗粒度、ESB（企业服务总线）通信、协议重（SOAP）。
*   **微服务**：SOA 的演进，更细粒度、独立部署、独立数据库、轻量级通信（HTTP/REST/gRPC）、去中心化。

**【微服务七大核心组件】**
1. 注册中心（服务注册与发现）
2. API 网关（统一入口、路由）
3. 服务（核心业务逻辑）
4. 分布式缓存（加速读取）
5. 负载均衡（请求分发）
6. 配置中心（统一管理配置）
7. 权限控制（认证授权）

**【微服务五大特点】**
单一职责、服务自治、DDD领域驱动、API优先、持续交付。

**【架构演进对比（极简速记）】**
*   **单体**：简单，但扩展差、部署难（小项目）。
*   **分布式**：按业务拆分独立部署，但运维复杂（中大规模）。
*   **集群**：同业务多实例，高可用，但需解决状态同步（高可用要求）。
*   **微服务**：服务自治、独立演进，但需解决分布式事务与服务治理（大型复杂系统）。
