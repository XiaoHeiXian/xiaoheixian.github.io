在初始阶段，网站只需要一个服务器即可满足需求。在这个阶段，系统简单，部署容易，但无法应对高并发和高负载的情况。

**阶段架构示意图：**
- 客户端发起 http 请求，访问 Tomcat。
- Tomcat 部署后端代码。
- 后端代码响应前端页面（包含商品展示、商品销售等模块）。
- 后端代码同时与数据库进行交互。

**这个阶段的特点：**

（1）系统架构简单：通常只有一个服务器处理所有任务，包括应用服务、数据服务和文件资源等，但扩展性和可靠性差。

（2）重复开发：团队协作效率差，相同功能可能在不同业务的项目中被重复开发，比如短信发送、支付等。

（3）新功能上线周期变长：公共 API 变更导致策略工作量剧增、新特性无法独立部署和交付。

---

💡 **面试速记（八股提炼）**

**【什么是单体架构？】**
所有的功能模块（如用户、订单、支付）和组件（如数据库、前端资源）全部打包在一个应用中，部署在同一台服务器上。

**【优点（只背初期）】**
架构简单，开发、测试、部署容易。

**【缺点（高频考点，引出分布式/微服务的原因）】**
1. **扩展性差**：只能做整体扩容，浪费资源；无法应对高并发。
2. **可靠性差**：单点故障，一挂全挂。
3. **维护成本高**：代码耦合严重，牵一发而动全身（改个公共API全站受影响）。
4. **团队协作难**：容易重复造轮子（如多个模块各自写一套短信发送），新功能无法独立上线。
