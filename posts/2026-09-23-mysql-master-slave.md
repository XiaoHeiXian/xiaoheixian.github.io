1、主从复制

MySQL 的主从复制（replication）是一种数据库技术，允许一个（或多个）MySQL 服务器（从服务器）复制另一个 MySQL 服务器（主服务器）上的数据。这种机制主要用于提高数据读取的性能和可用性，通过将查询负载分散到多个服务器上。

**主从复制示意图说明：**
- Master（主库）：数据发生变更（data change），写入二进制日志（binlog）。
- Slave（从库）：
  - I/O thread：读取主库的 binlog，写入到从库的中继日志（Relay log）。
  - SQL thread：读取 relay log 中的日志事件并且重做，以改变数据。

MySQL 主从复制涉及三个步骤：
（1）主库：Master 主库在事务提交时，会把数据变更记录在二进制日志文件 Binlog 中。
（2）I/O 线程（从库）：从库中由 IOthread 线程负责读取主库的二进制日志文件 Binlog，写入到从库的中继日志 Relay Log。
（3）SQL 线程（从库）：读取 relay log 中的日志事件并且重做，以改变数据。

2、读写分离

读写分离指的是将读与写请求分发到不同的数据库实例进行处理，减少单台服务器的压力，提高整体吞吐量。

（1）一主多从

主数据库（Master）负责写操作，从数据库（Slave）负责读操作，这种架构可以实现读写分离，提高系统的并发处理能力。这种架构过于简单，如果主节点宕机，就无法处理写请求，只能处理读请求了。

（2）双主多从

假设配置 2 台主数据库 m1 和 m2，2 台从数据库 s1、s2。由 m1 负责处理写操作，而 m2、s1、s2 均处理读请求。当 m1 不可用时，会自动切换为由 m2 处理写操作。在这种架构中，不光需要配置 s1 s2 分别为 m1 m2 的从库，同时也需要配置 m1 m2 互为对方的从库。

主从读写的架构不仅能够进行分流，解决高并发访问压力，同时还可以对数据进行备份，并提高可用性。

💡 **速记**

**【主从复制核心原理】**
主库（Master）写 Binlog -> 从库（Slave）的 IO 线程拉取并写入 Relay Log -> 从库的 SQL 线程重放 Relay Log。

**【读写分离核心思想】**
主库只负责写（增删改），从库只负责读（查询），通过分流降低单机压力，提高系统吞吐量。

**【两种读写分离架构】**
*   **一主多从**：主写从读。**缺点**：主库宕机则整个系统无法写入。
*   **双主多从**：两台主库互为主从。**优点**：解决单点故障，主库挂掉可自动切换另一台主库顶替写操作。

**【主从读写的最终收益】**
1. 分流高并发访问压力（读写分离）。
2. 数据备份（从库作为热备）。
3. 提高整体系统可用性（故障切换）。
