1、什么是分库分表

分库分表是通过数据库拆分策略，将单一数据库/表的数据分布到多个数据库/表的架构设计。主要解决单机数据库面临的四大瓶颈：

（1）存储瓶颈：单机磁盘容量限制。
（2）I/O 瓶颈：热点数据太多，数据库缓存不足，产生大量磁盘 IO，效率较低。
（3）网络瓶颈：并发请求数据太多，单机带宽不够。
（4）CPU 瓶颈：排序、分组、连接查询、聚合统计等 SQL 会耗费大量的 CPU 资源，请求数太多，CPU 出现瓶颈。
（5）连接瓶颈：单数据库连接数限制。

2、拆分维度

分库分表分为垂直和水平两种核心拆分维度：

（1）垂直拆分数据库：按业务模块划分数据（分布式架构），把所有表按业务领域拆分到不同的数据库。例如，分为用户库、商品库、订单库。

拆分示意图说明：
- 拆分前：Tomcat 连接一个庞大数据库，含3个库（shop_user, shop_goods, shop_order），总数据量 100G。
- 拆分后：3个库独立部署在不同 IP 上（192.168.200.100, .101, .102），shop_user 10G，shop_goods 50G，shop_order 40G。

这样拆分的好处：
- 业务解耦，降低耦合度
- 隔离故障影响范围
- 支持按业务特性选择存储引擎

同时也带来挑战：
- 需要进行分布式事务管理
- 遇到跨库关联查询时增加困难，需要跨服务查询

（2）垂直拆分数据表：把原来有很多列的表拆分成多个表，原则是：
- 高频访问字段与低频字段分离：把常用、不常用的字段（字段具有明显冷热特征）拆分，例如用户登录可以只存储登录名和密码，其它信息可以分表存储。
- 存在大字段（BLOB/TEXT）的表拆分：把大字段独立存放在一个表中，例如用户信息表中用户简历，商品表中商品详情等信息可以分表存储。

（3）水平拆分数据库或数据表

当单表数据量达到数百万至千万级别时，需要根据实际访问模式、查询性能、硬件配置等因素综合评估是否需要分表。一般建议：
- 数据量在 500 万以内且查询性能良好：优先优化索引和 SQL
- 数据量超过 500 万且出现性能瓶颈：考虑水平分表
- 数据量超过 1 亿：强烈建议分库分表

实际决策应基于压测和监控数据，而非单纯依赖数据量阈值。当达到分表要求时，我们对表进行拆分，我们可以把表的一部分数据拆分到另外一个数据库。将同一业务数据分布到多个数据库实例就是水平拆分。例如将订单数据库分别存储在数据库服务器 1 和数据库服务器 2 中，在应用程序中实现逻辑来决定将数据发送到哪个数据库实例，如通过简单的哈希函数或基于数据的某些属性（如用户 ID、部门 ID 等）来决定。

水平拆分示意图说明：
- Tomcat 连接4个同等大小的商品库（shop_goods），总数据量 50G。
- 拆分后：4个库独立部署在不同 IP 上，数据量分别为 20G、15G、15G 等。

3、数据库中间件

（1）什么是数据库中间件

数据库中间件是一类连接软件组件和应用的计算机软件，以便软件各部件之间的通信。

我们现在普遍的 Java 应用程序都是直接连接了 MySQL 数据库进行读写操作，也就是我们在 Java 中的配置文件等定义了 mysql 的数据源，直接连接到了我们的 mysql 数据库，但是当我们需要用到了多个数据库，这个时候我们需要多配置数据源去连接我们的多个数据库，这个时候我们进行 sql 操作的时候就会很麻烦，因为 Java 与数据库有了一个紧密的耦合度，但是如果我们 在 Java 应用程序与 mysql 中间使用了数据库中间件，我们只需要访问这个中间件就可以了，至于数据源等问题，中间件会直接帮我们搞定。

（2）为什么要使用

- 解决单机数据库性能瓶颈：在处理大规模数据和高并发访问时，单机数据库可能会遇到性能瓶颈。数据中间件通过数据分片（垂直和水平拆分）和负载均衡，将数据分布到多个数据库实例中，从而提高系统的并发处理能力和整体性能。
- 提供数据分片功能：中间件支持将数据水平切分到多个数据库中，每个分片只存储部分数据，这样可以大大减小单个数据库的压力。同时，通过自定义分片规则，可以灵活地根据业务需求进行数据分布。
- 实现读写分离：中间件可以将写操作(如 INSERT、UPDATE、DELETE)路由到主数据库，将读操作(如 SELECT)路由到从数据库。这种读写分离的方式，可以提高读操作的响应速度，并降低主数据库的压力。

（3）常用的数据中间件

- Apache ShardingSphere（当前最主流）：由京东开源的分布式数据库中间件生态圈，包含 Sharding-JDBC（轻量级 Java 增强）、Sharding-Proxy（数据库代理）、Sharding-Sidecar（云原生网格）。已升级为 Apache 顶级项目，社区活跃，支持分库分表、读写分离、分布式事务、数据加密等功能。
- Mycat：开源社区在阿里 Cobar 基础上二次开发的中间件，曾广泛使用。近年来社区活跃度下降，逐步被 ShardingSphere 替代。
- MySQL Router：MySQL 官方推出的轻量级中间件，支持读写分离和故障转移，功能相对简单。
- Vitess：由 YouTube 开源，受 Google 内部系统启发，支持大规模 MySQL 集群分片管理，适合超大规模场景。

💡 **速记**

**【为什么需要分库分表？】**
单机数据库面临五大瓶颈：存储容量、磁盘 I/O、网络带宽、CPU 算力、连接数限制。单靠升级硬件（垂直扩展）成本高且存在物理极限。

**【怎么拆？（拆分维度）】**
1. **垂直拆分（按业务/字段）**：
   *   **垂直分库**：按业务模块拆（如用户、订单、商品库），解决耦合，但带来分布式事务和跨库 JOIN 问题。
   *   **垂直分表**：冷热字段分离，大字段（BLOB/TEXT）单独建表。
2. **水平拆分（按数据行）**：
   *   **水平分库/分表**：同一业务数据分散到多个库/表。通过哈希或业务属性（如用户ID）路由。

**【什么时候分？（参考阈值）】**
*   500万以内：优先优化索引和 SQL。
*   超500万且出现瓶颈：考虑水平分表。
*   超1亿：强烈建议分库分表。
*   核心原则：基于压测和监控数据决策，而非死守阈值。

**【拆分后如何访问？】**
引入**数据库中间件**。它屏蔽底层分片逻辑，Java 应用只需连接中间件。
核心功能：数据分片、读写分离、分布式事务。
主流选型：
*   **ShardingSphere**（京东开源，Apache顶级，当前主流）
*   **Mycat**（阿里Cobar衍生，逐步被替代）
*   **MySQL Router**（官方轻量级）
*   **Vitess**（YouTube开源，超大规模）
