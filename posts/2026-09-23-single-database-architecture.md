单数据库是指一个应用只使用一个数据库服务器。

**架构示意图说明：**
- Tomcat 通过 JDBC 直接连接唯一的数据库服务器。
- 所有的读写请求都集中在这一台数据库上。

在 Java 应用程序中，单数据库访问可能会遇到多种瓶颈，因为 Java Web 项目直接通过 JDBC 连接单一的数据库，读写扎堆在一块，单库上的机器 IO 及 CPU 性能很快达到上限。这些问题通常涉及到性能优化和资源管理。以下是一些常见的数据库访问瓶颈及其解决方案：

（1）数据库连接池耗尽

瓶颈 1：如果应用程序频繁地创建和销毁数据库连接，而没有有效管理连接池，可能会导致连接池耗尽。

解决方案：使用连接池连接数据库，合理配置连接池的大小。例如，根据数据库服务器的承载能力和并发用户数来设置最大连接数和最小空闲连接数，确保连接池配置正确（如最大空闲时间、连接测试查询等）。

（2）SQL 查询效率低

瓶颈 2：复杂的、未优化的 SQL 查询会导致数据库响应缓慢。

解决方案：优化 SQL 查询，确保使用合适的索引。例如，避免在 WHERE 子句中使用函数，这可能导致索引失效，减少数据检索量，只查询需要的列或分页查询。

（3）并发访问冲突

瓶颈 3：在高并发环境下，多个线程或进程同时访问数据库可能导致锁争用或死锁。

解决方案：使用乐观锁或悲观锁策略。合理设计事务的大小和隔离级别，定期检查并解决死锁问题。

（4）缓存策略不当

瓶颈 4：不使用或错误使用缓存策略可能导致重复查询数据库。

解决方案：使用数据库级的缓存。例如，Redis 缓存。定期清理过时的缓存数据。

通过上述方法，你可以识别和解决 Java 应用程序中访问数据库时可能遇到的各种瓶颈。针对具体问题，可能需要结合多种策略来达到最佳性能。

但是，服务器的 CPU、内存和 I/O 性能直接影响 MySQL 的并发处理能力。MySQL 理论上可以设置的最大并发连接数为 16384 个，但实际并发量取决于服务器的 CPU 核心数、内存大小、硬盘 I/O 性能以及网络带宽等，如果单靠通过提高服务器的性能来解决高并发处理能力是不现实的。

在互联网业务爆发式增长的时代背景下，传统单数据库架构面临着三大核心挑战：海量数据存储、高并发访问压力、业务连续性保障。

💡 **速记**

**【什么是单库架构？】**
一个应用对应一个数据库，所有读写请求全部落在这一个库上，通过 JDBC 直连。

**【四大常见瓶颈与解法】**
1. **连接池耗尽** -> 合理配置连接池（最大连接数、最小空闲数、超时时间等）。
2. **SQL 效率低** -> 优化索引，避免 WHERE 中使用函数导致索引失效；只查所需列或分页。
3. **并发冲突** -> 采用乐观锁/悲观锁；合理设计事务大小和隔离级别；防死锁。
4. **缓存策略不当** -> 引入 Redis 等缓存，缓解数据库读压力，定期清理过期缓存。

**【架构局限与挑战】**
*   **硬件上限**：单机 CPU、内存、I/O 有物理极限，理论最大连接数 16384，实际远低于此，无法单纯靠“升配”解决高并发。
*   **三大核心挑战**：海量数据存储、高并发访问压力、业务连续性保障。（这三大挑战也是后续引入分布式数据库、读写分离、分库分表的核心原因）
