1、定义

流量控制是对进入服务的请求流量进行拦截、限速、排队、拒绝，避免瞬时高并发打垮服务。

2、流控规则

Sentinel 流量控制规则，用于对接口 / 自定义资源的访问流量进行限制，防止瞬时高并发、突刺流量压垮服务、数据库，是保障服务稳定的第一道防护手段。

当请求流量超过设定阈值时，根据配置的流控模式和流控效果对多余请求做拦截、排队、延迟处理。

新增流控规则界面包含以下参数：
- 资源名：/order/query
- 针对来源：default
- 阈值类型：QPS / 并发线程数
- 单机阈值：设置具体数值
- 是否集群：勾选框
- 流控模式：直接 / 关联 / 链路
- 流控效果：快速失败 / Warm Up / 排队等待

1）资源名

需要限流的目标标识，可以是接口 URL，也可以是 @SentinelResource 定义的自定义资源名称。

2）阈值类型

（1）QPS（每秒请求数，最常用）
限制每秒允许通过的请求总量，适合防突发高并发、秒杀防刷。
例：单机阈值 = 10：单台实例每秒最多放行 10 次请求，超过触发限流。

（2）并发线程数
限制接口同时处理的工作线程数量，防止线程池打满、服务阻塞。
例：阈值 = 20：最多 20 个线程同时执行业务，新请求直接拦截。

2）流控模式

（1）直接（默认）
仅对当前配置的资源本身做限流，请求到达该资源时直接判断是否超限。适用于普通独立接口限流的场景，大部分业务接口使用该模式。

【配置示例】
资源名：/order/create
阈值类型：QPS，单机阈值 5
流控模式：直接
效果：每秒超过 5 次创建订单请求，直接拦截。

（2）关联限流
监控关联资源，当关联资源流量达到阈值时，限流当前资源。例如有 A（读数据）、B（写数据）两个接口共用同一数据库，B 是写库接口（压力大），当 B 流量过高时，限制查询接口 A，保护数据库写入操作。
适用于读写分离保护场景，写接口流量暴增，自动限制查询接口，防止数据库崩溃。

【配置实例】
当前资源：/order/list（查询）
流控模式：关联
关联资源：/order/save（写入）
阈值 QPS=20
效果：当新增订单接口每秒超过 20 请求，查询订单接口直接限流，优先保障写入。

（3）链路限流
只统计指定入口资源调用当前资源的流量，其他入口调用不受限制。适用于同一个底层公共方法被多个上层接口调用的场景，仅限制某一个调用方的流量。例如公共支付校验方法 payCheck()，被下单、充值两个接口调用，只限制下单调用该方法的流量，充值接口不受影响。

【配置实例】
资源：payCheck
流控模式：链路
入口资源：/order/pay
阈值 QPS=10
效果：只有下单接口每秒调用校验超过 10 次才限流；充值接口调用无限制。

3）流控效果

流控效果是限流后的处理行为。

（1）快速失败（默认）
请求超过阈值直接拒绝，抛出 FlowException，返回限流提示。适用于普通查询、后台管理接口，不允许排队等待。瞬时高并发超过阈值，立即拦截，无等待。

（2）Warm Up（冷启动/预热）
系统启动初期缓慢提升阈值，逐步放开流量，避免冷启动瞬间大量请求压垮服务。底层采用令牌桶算法，初始只发放少量令牌，预热时长后达到设置阈值。适用于秒杀、定时任务、服务重启后易瞬间涌入大量请求的场景。

【配置实例】
QPS 阈值 = 100，预热时长 = 5 秒
效果：前 5 秒逐步放行流量，5 秒后稳定每秒 100 请求，防止刚启动瞬间并发打垮服务。

（3）排队等待（匀速排队）
漏桶算法，限制请求匀速通过，超出流量进入队列排队，设置最大等待超时时间。适用于允许短时间等待、不允许丢请求的业务（支付、订单提交）。

【配置示例】
阈值 QPS=5，排队超时 2000ms
效果：每秒匀速放行 5 个请求；多余请求进入队列，2 秒内未处理直接限流失效。

    }

    @Service
    @Slf4j
    public class ProductServiceImpl implements IProductService {
        @SentinelResource("stockCheck") // 标识资源

            return "创建成功";
        }
    }

💡 **速记**

**【什么是流量控制？】**
对进入服务的请求流量进行拦截、限速、排队、拒绝，避免瞬时高并发打垮服务。

**【流控规则四要素】**
1. **资源名**：接口 URL 或 @SentinelResource 自定义名称。
2. **阈值类型**：
   * **QPS**：每秒请求数，防突发高并发（最常用）。
   * **并发线程数**：限制同时处理的工作线程数量，防线程池打满。
3. **流控模式**：
   * **直接**：默认，仅对当前资源本身限流。
   * **关联**：关联资源（如写接口）超阈值时，限流当前资源（如读接口），保护数据库。
   * **链路**：只统计指定入口资源调用当前资源的流量，其他入口不受限。
4. **流控效果**：
   * **快速失败**：默认，超阈值直接拒绝，抛 FlowException。
   * **Warm Up（冷启动/预热）**：启动初期缓慢提升阈值，底层令牌桶算法。
   * **排队等待（匀速排队）**：漏桶算法，请求匀速通过，多余请求排队等待，超时失效。

**【四大实战案例核心配置】**
*   **案例一（快速失败）**：/order/query，QPS=5，直接，快速失败。效果：每秒仅放行 5 个，其余拒绝。
*   **案例二（预热）**：/order/query，QPS=20，直接，Warm Up，预热时长 3 秒。效果：3秒内逐步从少量放行到每秒20个，防冷启动雪崩。
*   **案例三（关联限流）**：/order/query，QPS=5，关联 /order/update，快速失败。效果：写接口压力大时，读接口被限流，优先保写入。
*   **案例四（链路限流）**：stockCheck，QPS=5，链路，入口 /product/seckill，快速失败。效果：仅限秒杀调用库存校验，普通下单不受影响。
