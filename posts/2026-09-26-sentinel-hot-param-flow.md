1、什么是热点参数限流

热点参数限流是流量控制的一个特例，流量控制控制的是资源，而热点可以控制参数，如方法是一个资源，热点就是方法的参数。

1）定义

热点 = 高频访问的参数值（爆款商品 ID、热门直播间 ID、高频用户 ID、秒杀商品 ID）

热点参数限流是参数粒度的精细化限流：统计接口指定位置的请求参数，对单个参数值单独限流，只拦截高频访问的热点参数，不影响其他普通参数。

- 普通全局限流：限制整个接口总 QPS，所有参数共享阈值；
- 热点参数限流：每个参数独立统计，爆款单独限流，冷门参数不受限制。

2）典型业务场景

（1）商品详情接口：爆款商品 productId=10001 每秒上千访问，冷门商品几乎无流量；单独限制爆款，保护数据库缓存不被击穿。
（2）秒杀接口：限量商品短时间大量请求，防止单商品打垮所有服务。
（3）用户接口：恶意高频刷单个用户数据，限制该用户 ID 访问频率。
（4）直播间接口：头部主播直播间流量爆炸，单独限流不影响小主播。

3）底层实现原理

- 采用 LRU（最近最少使用淘汰算法）缓存自动保留访问 Top K 热点参数，淘汰低频冷参数，节约内存；
- 滑动时间窗口统计每个参数独立 QPS；
- 仅支持 QPS 限流模式（不支持并发线程数）。

2、前置硬性前提

必要条件：不满足则规则完全不生效。

（1）必须使用 @SentinelResource 注解标记资源：普通 Web URL 过滤器模式不支持热点参数统计，无法识别请求参数，只能注解模式使用热点限流。
（2）注解方法必须携带参数，参数索引和控制台配置严格对应：参数索引 paramIdx 从 0 开始：

    // paramIdx=0 -> productId; paramIdx=1 -> userId
    @GetMapping("/detail")
    @SentinelResource("productDetail")
    public String detail(Long productId, Long userId)

3、实践

【案例】：对热点商品和用户限流

资源名：productDetail（和 @SentinelResource(value) 完全一致）
限流模式：QPS 模式（热点仅支持 QPS）
参数索引：0 取第一个参数 productId 做热点统计
- 需求1：2号商品 QPS 不得超过 3。
- 需求2：1号是下架商品，不允许访问。
参数索引：1 取第二个参数 UserId 做热点统计
- 需求1：每个用户秒杀 QPS 不得超过 1，避免用户疯狂下单。

（1）业务接口

在 mall-test-service 的 ProductController 添加方法：

    @GetMapping("/detail")
    @SentinelResource("productDetail")
    public String getProductDetail(
            @RequestParam Long productId,
            @RequestParam Long userId
    ) {
        log.info("商品详情查询，商品 ID: {}，用户 ID: {}", productId, userId);
        return "商品详情查询成功";
    }

（2）规则配置

按照需求配置规则：

① 创建 productId 限流
设置所有商品无限制（QPS 阈值为 1000000）：

    资源名：productDetail
    限流模式：QPS 模式
    参数索引：0
    单机阈值：1000000
    统计窗口时长：1 秒
    是否集群：不勾选

配置限流商品：
在热点规则中找到刚创建的热点规则-编辑-高级选项，分别添加两个参数例外项：
- 参数值 1（商品号为1），限流阈值 0（表示没有流量）
- 参数值 2（商品号为2），限流阈值 3

② 创建 userId 限流

    资源名：productDetail
    限流模式：QPS 模式
    参数索引：1
    单机阈值：1
    统计窗口时长：1 秒
    是否集群：不勾选

（3）测试

注意：在测试前先关闭全局异常处理，控制器抛出的异常被全局异常处理器捕获并处理了。

① 测试商品 ID=1
使用 Jmeter 测试：
- 重新创建线程组：
  - 线程数 30
  - 启动时间 3
  - 循环次数 1
- 添加 HTTP 请求：/product/detail
- 参数配置：productId=1，userId=116
- 添加监听器（查看结果树、聚合报告）

（4）效果验证
运行 Jmeter 后，观察 Sentinel 控制台的“热点数据”或“簇点链路”页面。
由于商品 ID=1 设置了 QPS 阈值为 0，所以所有针对商品 1 的请求都会被拒绝。
查看 Jmeter 的“聚合报告”，错误率应为 100%（或接近），异常信息为 `Blocked by Sentinel (flow limiting)`。
如果修改请求参数为 productId=2，则会受到 QPS 限制为 3 的约束，每秒放行 3 个请求，其余被拒绝。

同理，测试 userId 限流时，只需修改 Jmeter 中的参数（如 userId=116），由于 userId 限流阈值为 1，同一用户一秒内只会通过 1 个请求。

💡 **速记**

**【什么是热点参数限流？】**
流量控制的一种特例。普通流控控制的是资源（接口），热点参数限流控制的是参数。针对高频访问的参数值（如爆款商品ID）单独限流，避免影响其他普通参数。

**【与全局限流的区别】**
*   **全局限流**：限制整个接口总 QPS，所有参数共享阈值。
*   **热点参数限流**：每个参数独立统计，爆款单独限流，冷门参数不受限。

**【底层实现原理】**
1. LRU（最近最少使用）缓存保留 Top K 热点参数，淘汰低频参数。
2. 滑动时间窗口统计每个参数独立 QPS。
3. 仅支持 QPS 限流模式（不支持并发线程数）。

**【两大硬性前提（不满足则不生效）】**
1. 必须使用 `@SentinelResource` 注解标记资源（普通 Web URL 不支持）。
2. 注解方法必须携带参数，参数索引 `paramIdx` 从 0 开始（paramIdx=0 对应第一个参数，paramIdx=1 对应第二个参数）。

**【实战配置核心】**
*   资源名：`productDetail`。
*   **参数索引 0（productId）**：设置全局 QPS 阈值 1000000（相当于无限制），然后利用“高级选项”添加参数例外项：
    *   商品 1：阈值 0（下架不允许访问）。
    *   商品 2：阈值 3（爆款限制 QPS 3）。
*   **参数索引 1（userId）**：设置单机阈值 1，限制每个用户秒杀 QPS 不超过 1。
