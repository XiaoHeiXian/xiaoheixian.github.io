1、实体-联系

本系统有四个实体：用户、商品、订单和订单明细：

（1）用户和订单：一对多（一个用户可以有多个订单）

（2）订单和订单明细：一对多（一个订单包含多个商品明细）

（3）订单明细和商品：多对一（多个明细可以指向同一个商品，但订单中同一商品只出现一次，由复合主键约束）

这样设计后，将多对多关系（用户和商品）被拆解为两个一对多关系，中间的订单和订单明细共同承担了关联职责，同时订单明细作为弱实体保证了订单数据的完整性和历史一致性。

E-R 图结构：
用户 (1) --拥有--> (N) 订单 (1) --包含--> (N) 订单明细 (N) --被包含--> (1) 商品

2、实体-属性

用户与商品在用户服务和商品服务中已设计，本节只涉及订单和订单明细的设计。

（1）订单

属性：订单编号、提交时间、支付时间、发货时间、用户账号、收货人、收货人手机、收货人地址、用户账号、收货人地址编号、订单状态、订单类型、确认收货状态、删除状态

订单属性说明：
- 订单编号
- 提交时间
- 支付时间
- 发货时间
- 用户账号
- 收货人
- 收货人手机
- 收货人地址
- 收货人地址编号
- 订单状态
- 订单类型
- 确认收货状态
- 删除状态
- 订单总金额
- 支付方式
- 交易流水号

（2）订单明细

属性：编号、订单 id、商品 SKU_ID、商品名称、图片地址、销售价格、购买数量、金额合计

订单明细属性说明：
- 编号
- 订单 id
- 商品 SKU_ID
- 商品名称
- 图片地址
- 销售价格
- 购买数量
- 金额合计

3、关系转换

为了在数据库中实现一对多关系（或一对一关系），通常会在“多”的一方中添加一个外键字段，该字段引用“一”的一方的主键。

以下是将订单、订单明细转换为关系模式后的相关信息，并以表格形式呈现：

（1）订单表 (order_info)

| 字段名 | 类型 | 长度 | 说明 |
| :--- | :--- | :--- | :--- |
| order_id | varchar | 64 | 主键，订单编号 |
| create_time | datetime | - | 提交时间 |
| user_id | bigint | - | 用户 ID（关联用户表） |
| total_amount | double | 10,2 | 订单总金额 |
| pay_type | int | - | 支付方式：0->未支付；1->支付宝；2->微信；3->银行卡 |
| status | int | - | 订单状态：0->待付款；1->待发货；2->已发货；3->已完成；4->已关闭；5->无效订单 |
| order_type | int | - | 订单类型：0->正常订单；1->秒杀订单 |
| address_id | varchar | 256 | 收货人地址编号 |
| transaction_id | varchar | 32 | 交易流水号 |
| confirm_status | int | - | 确认收货状态：0->未确认；1->已确认 |
| deleted | int | - | 删除状态：0->未删除；1->已删除 |
| payment_time | datetime | - | 支付时间 |
| delivery_time | datetime | - | 发货时间 |
| receive_time | datetime | - | 确认收货时间 |
| update_time | datetime | - | 修改时间 |

（2）订单明细表 (order_items)

| 字段名 | 类型 | 长度 | 说明 |
| :--- | :--- | :--- | :--- |
| id | bigint | - | 主键，明细自增编号 |
| order_id | varchar | 64 | 外键，关联订单表(order_id) |
| price | double | 10,2 | 销售价格（快照） |
| quantity | int | - | 购买数量 |
| sku_id | bigint | - | 商品 SKU_ID |
| sku_name | varchar | 128 | 商品名称（快照） |
| image | varchar | 128 | 图片地址（快照） |
| amount | double | 10,2 | 金额合计（price × quantity） |

💡 **速记**

**【实体关系设计】**
*   **关系拆解**：用户与商品是多对多，通过拆解引入订单和订单明细。变成：用户(1)-订单(N)，订单(1)-订单明细(N)，订单明细(N)-商品(1)。
*   **外键放置**：在“多”的一方（订单表、订单明细表）添加外键，指向“一”的一方的主键。订单明细作为弱实体保证数据完整性。

**【订单表(order_info)核心字段】**
*   **主键**：`order_id` (varchar 64)
*   **外键**：`user_id` (关联用户)
*   **关键业务字段**：`total_amount` (总金额)、`pay_type` (支付方式 0-3)、`status` (订单状态 0-5)、`order_type` (订单类型 0正常/1秒杀)。
*   **时间字段**：创建、支付、发货、收货、修改时间。

**【订单明细表(order_items)核心字段】**
*   **主键**：`id` (自增)
*   **外键**：`order_id` (关联订单表)
*   **核心**：`sku_id` (商品ID)、`quantity` (数量)、`amount` (合计=price*quantity)。
*   **快照字段（高频考点）**：`price`、`sku_name`、`image`。这些字段必须存成快照，防止商品后续修改信息导致订单历史数据错乱。
