## 1 智能体的核心定义与核心价值

智能体（Agent，也常称为 AI Agent）是人工智能领域中能够感知环境、自主决策、执行动作并优化结果以实现预设目标的自主系统。

它突破了传统大型语言模型（LLM）“只说不做”的局限，通过“感知 - 思考 - 行动 - 观察”的闭环，将 AI 能力从“文本生成”升级为“任务执行”，成为连接 AI 与现实世界的核心载体。

原生 LLM 仅能依托训练数据集完成被动文本输出，不存在自主思考、外部操作的能力，天然存在知识滞后、幻觉编造的缺陷。

基础 Chain 链路需要开发者提前写死全部执行流程，无论用户提问如何变化，都只能机械执行预设步骤，无法适配模糊、多目标的复杂需求。

而 LangChain 智能体依托 ReAct 推理行动机制，完整实现“思考决策 - 工具执行 - 结果观察 - 迭代优化”的循环流程，能够自主拆解任务、筛选外部资源，从根源弥补原生大模型与固定链路的各项短板，实现真正的自主智能交互。

一句话总结：AI 智能体能够自主感知外部环境、解析用户自然语言目标、自主推理执行逻辑、主动调用外部工具、接收环境反馈迭代、输出标准化合规结果的智能化执行系统。

## 2 智能体的四大核心特征

完整工业级可投入使用用的 LangChain 智能体必须同时具备四大核心特征，这也是区分普通 LLM 问答、固定脚本与标准智能体的判定依据，四项缺一不可：

（1）自主性（Autonomy）：

无需人工分步干预任务流程，智能体可基于用户目标与当前环境信息自主判断“需要做什么、以何种顺序完成”，自主筛选适配工具、拆分子任务，规划完整执行路径，全程不需要开发者预设全套执行脚本，独立走完完整任务闭环。

（2）交互性（Interactivity）：

支持双向动态交互能力，智能体可同时对接用户输入、本地文档、第三方网络 API、内存存储等多类内外资源，接收工具、用户的反馈信息后，动态调整后续推理与执行策略，不会机械重复固定操作。

（3）目标导向性（Goal-Oriented）：

智能体全部思考、执行动作都围绕用户核心需求展开，内置复杂任务拆解逻辑，能够自动区分有效步骤与无效冗余操作，对子任务划分优先级，优先完成贴合用户目标的执行流程，杜绝无意义循环调用。

（4）适应性（Adaptability）：

依托内置记忆系统留存全部交互经验，能够适配残缺提问、模糊口语、场景变更等各类不确定输入，不会单一、机械地套用同一套应答逻辑，可根据对话上下文灵活调整推理思路。

## 3 智能体主流分类与适配场景

根据智能体的记忆能力、决策逻辑、应用复杂度，行业将智能体划分为六大主流类型。结合本课程智能搜索开发主线，课堂实训以目标导向智能体、学习型智能体为核心讲解对象，其余类型作为拓展理论补充。

（1）反应式智能体（Reactive Agent）：

无记忆模块，仅依据当前单次输入即时给出响应，逻辑极简、响应速度快，适配工业设备监控、固定单指令应答等轻量化场景，不存在多轮对话交互能力。

（2）基于模型的智能体（Model-Based Agent）：

内置环境状态模拟逻辑，可预判工具调用、外部接口返回的结果变化，适配输入动态变化的交互场景，能够根据预判调整工具调用顺序。

（3）目标导向智能体（Goal-Based Agent）：

以用户明确任务目标为核心，原生支持复杂任务分层拆解，是商用智能问答、私有知识库检索系统的主流实现类型，本课程天气、知识库工具案例均基于该类型开发。

（4）效用函数智能体（Utility-Based Agent）：

引入成本、优先级、容错率等量化评估规则，可在多条可行执行路径中筛选最优方案，适配资源分配、多维度方案对比等优化类场景。

（5）学习型智能体（Learning Agent）：

依托长期记忆存储历史交互数据，每一轮对话后自动优化自身决策逻辑，交互次数越多应答精准度越高，适配长期个性化交互项目。

（6）多智能体系统（Multi-Agent System）：

由多个功能差异化智能体分工协作，分别负责检索、计算、文案生成等细分模块，适配智慧城市、大型数据分析等超复杂工程项目。

## 4 智能体完整架构与运行闭环

LangChain 体系下所有标准智能体统一遵循五层分层架构，五层模块层层联动、数据双向流转，共同支撑“感知 - 记忆 - 推理 - 规划 - 执行”的完整自主运行闭环，各层级权责完全解耦，可单独替换、灵活组合。

（1）感知层：

核心功能为全量信息采集与标准化封装，统一接收用户自然语言提问、工具返回原始数据、历史对话记录等全部输入内容，将各类零散信息转换为 LangChain 标准化消息对象，向下传递至记忆层与推理层，是智能体所有输入信息的统一入口。

（2）记忆层：

负责全部交互数据的存储与调取，分为短期会话内存记忆、Redis 长期持久化记忆两类，完整留存对话上下文、工具执行中间结果，保障多轮连续提问时，智能可读取历史内容连贯作答，是智能体适应性特征的底层支撑。

（3）推理层：

智能体的核心决策大脑，载体为 LLM 大模型，依托 ReAct 机制完成语义理解、需求拆解、工具匹配、参数生成全部推理工作，接收感知层、记忆层传递的消息后，输出下一步行动指令。

（4）规划层：

负责复杂任务调度，接收推理层的核心目标后，将单一复杂需求拆分为有序子任务，划分子任务执行优先级，避免无序重复调用工具，简化推理层的决策负担。

（5）执行层：

承载所有外部操作，由各类自定义 Tool 工具集合组成，接收规划层下发的行动指令，完成网络请求、文档读取、数值计算等具象操作，执行完成后将结果封装为工具消息，反向回流至推理层，形成迭代闭环。

智能体标准化完整工作闭环完整流转流程：用户输入自然语言请求进入感知层 -> 感知层将内容封装为标准化消息 -> 记忆层读取当前会话全部历史消息补充上下文 -> 推理层结合系统提示、历史消息完成自主推理，判断是否需要调用工具、调用哪一款工具、传入对应参数 -> 执行层运行指定工具获取外部原始数据，生成工具消息 -> 工具消息回流至推理层。

## 5 LangChain 智能体核心组件

LangChain 官方将智能体五层架构工程化为五大解耦核心组件，五大组件可自由搭配组合，配套实训可按需删减模块，组件功能、实操示例如下表 1 所示：

表 1 Agent 核心组件

组件：Agent（智能体）

作用：全局任务决策者与调度器，统筹全流程，解析用户目标、推理执行逻辑、选择匹配工具、规划执行流程。

示例：自主判断知识类提问检索知识库、实时信息提问调用联网工具。

组件：LLM（大模型）

作用：核心推理引擎，提供语义理解、逻辑推理、文本生成、结构化输出能力，支撑 Agent 所有决策逻辑。

示例：硅基流动 Qwen3-8B 模型，解析指令、生成工具调用参数、整合输出答案。

组件：Tools（工具集）

作用：能力拓展执行器，弥补大模型知识滞后、无实操能力的短板，对接外部资源、完成具象化操作。

示例：时间查询、知识库检索、文本解析、联网搜索工具。

组件：Memory（记忆系统）

作用：上下文存储载体，留存对话历史、任务中间数据，保障多轮交互连贯、任务可迭代优化。

示例：内存短期会话记忆、Redis 长期持久化记忆。

组件：OutputParser（输出解析器）

作用：规整模型自由文本输出，转化为标准化结构化数据，适配项目对接、下游系统调用。

示例：JSON 标准化输出、自定义字段解析、格式纠错。

五大核心组件协同工作：Agent 作为总调度，LLM 作为大脑进行推理，Tools 作为手脚执行外部操作，Memory 提供历史上下文记忆，OutputParser 负责将最终结果转化为下游系统可处理的标准结构。它们共同支撑了智能体“感知 - 记忆 - 推理 - 规划 - 执行”的完整运行闭环。

## 6 流程图文字推演

### 智能体五层架构运行闭环

用户输入自然语言请求 --> 感知层接收并封装为标准化消息 --> 记忆层读取历史会话补充上下文 --> 推理层（LLM）结合系统提示与历史消息进行自主推理 --> 推理层判断是否需要调用工具及调用参数 --> 规划层拆解复杂任务并划分优先级 --> 执行层调用具体 Tool 执行外部操作 --> 获取外部原始数据并生成工具消息 --> 工具消息回流至推理层 --> 推理层整合结果生成最终输出 --> OutputParser 规整输出为结构化数据 --> 返回最终结果

### 智能体核心组件协作流程

Agent（总调度） --> 接收用户目标并解析 --> 调用 LLM 进行推理与工具选择 --> 通过 Tools 执行外部操作 --> 通过 Memory 存取历史上下文 --> 通过 OutputParser 格式化最终输出 --> 返回标准化结果

💡 **速记**

【核心考点】

智能体（Agent）的定义：能感知环境、自主决策、执行动作并优化结果的自主系统，核心是突破 LLM 的“只说不做”，实现“文本生成”到“任务执行”的升级。

四大核心特征：自主性、交互性、目标导向性、适应性。

五层架构：感知层（接收输入）、记忆层（存取历史）、推理层（LLM 决策）、规划层（任务拆解）、执行层（工具调用）。

五大核心组件：Agent、LLM、Tools、Memory、OutputParser。

【高频逻辑链】

智能体运行闭环：用户输入 --> 感知层封装 --> 记忆层补充上下文 --> 推理层决策 --> 规划层拆解任务 --> 执行层调用工具 --> 结果回流至推理层 --> 生成最终输出 --> OutputParser 结构化处理。

核心组件协同：Agent 调度 --> LLM 推理 --> Tools 执行 --> Memory 记忆 --> OutputParser 格式化。

【关键避坑】

普通的 LLM 问答或固定 Chain 脚本不能称为智能体，必须同时具备自主性、交互性、目标导向性与适应性四大特征。

OutputParser 在智能体链路中至关重要，它负责将 LLM 的自由文本转化为下游系统可对接的结构化数据（如 JSON），缺少这一步会导致系统集成困难。
