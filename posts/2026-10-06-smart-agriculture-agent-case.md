## 1、设置 System Prompt

固定，永久贴在 Context 最前面。

    你是一位资深的植保专家，说话风格像老农技站站长，朴实、直接。回答必须引用具体的农业技术规程或农谚，语气要接地气。绝不允许直接推荐具体农药品牌，只能推荐有效成分或防治方法。

## 2、用户输入 User Prompt

本轮具体任务。

    我家玉米地里发现很多虫子，叶片被咬得全是洞，怎么办？

## 3、系统把 System + User 拼接成完整 Context

System Prompt 长度约等于 80 tokens

User Prompt 长度约等于 30 tokens

总长度假设为 110 tokens，远小于 Context Window（32K），所以完整容纳，没有被截断。

## 4、分词器将中文转为多个 Token

每个 Token 对应唯一的 tokenId，这是模型真正在运算时的底层形态，给用户看的文字只是“翻译”出来的结果。

    文字：玉，Token（人类可读）：[玉]，tokenId（机器实际运算的数字）：24583
    文字：米，Token（人类可读）：[米]，tokenId（机器实际运算的数字）：10247
    文字：地，Token（人类可读）：[地]，tokenId（机器实际运算的数字）：33401
    文字：虫，Token（人类可读）：[虫]，tokenId（机器实际运算的数字）：8832
    文字：...，Token（人类可读）：...，tokenId（机器实际运算的数字）：...

模型内部实际处理的是：[24583, 10247, 33401, 8832, ...] 一串整数数组，而不是汉字本身。

## 5、Agent 内部开始规划

Agent 的“大脑”（LLM）拿到 Context 后，不是直接回答，而是自主决策：

思考路径：“用户问的是玉米虫害，但我不知道具体是什么虫、什么时期、当地气候如何，直接回答容易出错。”

决策：先调用 Tools（工具）获取外部信息，再综合回答。

## 6、Agent 调用 Tool（工具）

Agent 决定调用一个联网搜索工具，自动构造查询词：

    search("玉米 虫害 叶片 蛀洞 防治 技术规程")

搜索引擎返回结果，假设约 800 字，内容包括：

    “玉米主要虫害包括玉米螟、黏虫、棉铃虫……防治适期为喇叭口期，推荐使用含氯虫苯甲酰胺或苏云金杆菌（Bt）的有效成分……”

关键：这 800 字被追加进 Context Window，此时总 Token 数 = 110 + 800 字对应的 Token 数（约 1000 tokens）= 1110 tokens，仍然远小于 32K 的窗口限制，所以全部内容都在“桌面”上，模型随时可以回头看。

## 7、LLM 结合 System Prompt 的限制生成最终回答

System Prompt 里规定了：

- 说话像老农技站站长，朴实直接

- 必须引用技术规程或农谚

- 绝不能推荐具体农药品牌，只能推荐有效成分

于是模型生成回答：

    “哎呀，你这是玉米螟咬的，老话讲‘喇叭口期防一遍，穗期再防保丰产’。按 NY/T 1234-202X 玉米病虫害防治技术规程，喇叭口期用含氯虫苯甲酰胺或 Bt（苏云金杆菌）的药剂就行。具体哪个牌子你自己去农资店看，我这不能给你指定，得按当地经销商的实际货源来。”

## 8、检查是否完全遵守了 System Prompt

    System 要求：语气朴实、像老站长
    回答里是否满足：“哎呀”“老话讲”“你自己去农资店看”

    System 要求：引用农谚
    回答里是否满足：“喇叭口期防一遍，穗期再防保丰产”

    System 要求：引用技术规程
    回答里是否满足：“按 NY/T 1234-202X……”

    System 要求：不推荐具体品牌
    回答里是否满足：只推荐有效成分，明确说“不给你指定”

## 流程图文字推演

### 智慧农业助手 Agent 完整工作流程

用户提问（如：玉米地里发现虫子怎么办？） --> 拼接 System Prompt（资深植保专家）与 User Prompt --> 形成完整 Context --> 分词器转化为 tokenId 序列 --> Agent 内部规划（决定调用搜索工具） --> 调用外部 Tool（联网搜索相关防治技术） --> 工具返回结果并追加至 Context --> LLM 结合 System Prompt 约束生成回答 --> 检查回答是否符合系统提示词要求（语气、引用规程、不推荐品牌）

### 模型底层处理流程

用户输入文本 --> 分词器切分 Token --> 词表映射为 tokenId（如“玉”=24583） --> 模型内部进行数学运算（向量加减乘除） --> 输出 tokenId 序列 --> 词表反查映射回文字 --> 生成最终回答

💡 **速记**

【核心考点】

System Prompt 决定了模型的角色、语气和行为边界，权重极高。

Agent 的自主规划能力体现在：识别到知识盲区后，主动调用外部工具补充上下文，而非强行作答。

工具的返回结果会追加到 Context Window 中，模型结合这些外部数据生成最终回答。

【高频逻辑链】

拼接 Context（System + User） --> 分词与 tokenId 映射 --> Agent 决策调用 Tool --> 结果追加至 Context --> 生成受 System Prompt 约束的最终回答 --> 逐项校验 Prompt 规则。

【关键避坑】

System Prompt 的约束力虽然很强，但必须在生成后逐项校验（如语气、引用、品牌限制），以确保模型没有偏离预设指令。

Context Window 的容量是有限的，当对话或工具返回结果过长时，必须注意 Token 是否会溢出，导致历史信息或关键上下文被截断丢失。
