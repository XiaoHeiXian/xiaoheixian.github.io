## 1、什么是 elasticsearch

elasticsearch（ES）一个开源的分布式搜索引擎，可以用来实现搜索、日志统计、分析、系统监控等功能。具备非常多强大功能，可以帮助我们从海量数据中快速找到需要的内容。

## 2、elasticsearch 的优势

（1）支持分布式，可水平扩展

（2）高性能（基于倒排索引）

（3）提供 Restful 接口，可被任何语言调用

# 倒排索引

倒排索引的概念是基于 MySQL 这样的正向索引而言的。

## 1）正向索引

那么什么是正向索引呢？例如给下表（tb_goods）中的 id 创建索引，如果是根据 id 查询，那么直接走索引（聚合索引），查询速度非常快。但如果是基于 title 做模糊查询，只能是逐行扫描数据。

正向索引数据表结构如下：

    id | title | price
    1  | 小米手机 | 3499
    2  | 华为手机 | 4999
    3  | 华为小米充电器 | 49
    4  | 小米手环 | 49
    ... | ... | ...

正向索引的搜索流程如下（以搜索“手机”为例）：

![架构示意图](https://xiaoheixian.github.io/posts/assets/326_65.png)

① 用户搜索数据，条件是 title 符合“%手机%”

② 逐行获取数据，比如 id 为 1 的数据

③ 判断数据中的 title 是否符合用户搜索条件

④ 如果符合则放入结果集，不符合则丢弃。回到步骤 1

逐行扫描，也就是全表扫描，随着数据量增加，其查询效率也会越来越低。当数据量达到数百万时，就是一场灾难。

## 2）倒排索引

倒排索引中有两个非常重要的概念：

- 文档（Document）：用来搜索的数据，其中的每一条数据就是一个文档。例如一个网页、一个商品信息

- 词条（Term）：对文档数据或用户搜索数据，利用某种算法分词，得到的具备含义的词语就是词条。例如：我是中国人，就可以分为：我、是、中国人、中国、国人这样的几个词条。

创建倒排索引是对正向索引的一种特殊处理：

① 将每一个文档的数据利用算法分词，得到一个词条

② 创建表，每行数据包括词条、词条所在文档 id、位置等信息

③ 因为词条唯一性，可以给词条创建索引，例如 hash 表结构索引

倒排索引数据表结构如下：

    词条 (term) | 文档 id
    小米 | 1, 3, 4
    手机 | 1, 2
    华为 | 2, 3
    充电器 | 3
    手环 | 4

![架构示意图](https://xiaoheixian.github.io/posts/assets/327_65.png)

倒排索引的搜索流程如下（以搜索“华为手机”为例）：

① 用户输入条件“华为手机”进行搜索。

② 对用户输入内容分词，得到词条：华为、手机。

③ 拿着词条在倒排索引中查找，可以得到包含词条的文档 id：1、2、3。

④ 拿着文档 id 到正向索引中查找具体文档。

![架构示意图](https://xiaoheixian.github.io/posts/assets/328_65.png)

虽然要先查询倒排索引，再查询正向索引，但是无论是词条、还是文档 id 都建立了索引，查询速度非常快！无需全表扫描。

## 3）正向和倒排对比

（1）概念区别：

正向索引是最传统的，根据 id 索引的方式。但根据词条查询时，必须先逐条获取每个文档，然后判断文档中是否包含所需要的词条，是根据文档找词条的过程。

而倒排索引则相反，是先找到用户要搜索的词条，根据词条得到搜索词条的文档 id，然后根据 id 获取文档。是根据词条找文档的过程。

（2）优缺点：

正向索引：

优点：

- 可以给多个字段创建索引

- 根据索引字段搜索、排序速度非常快

缺点：

- 根据非索引字段，或者索引字段中的部分词条查找时，只能全表扫描。

倒排索引：

优点：

- 根据词条搜索、模糊搜索时，速度非常快

缺点：

- 只能给词条创建索引，而不是字段

- 无法根据字段做排序

# 8.1.3 流程图文字推演

## 正向索引搜索流程

用户搜索“手机” --> 执行 SQL：select * from tb_goods where title like '%手机%' --> 逐条数据扫描，判断是否包含“手机” --> 不符合，丢弃 --> 符合，存入结果集 --> 返回结果

## 倒排索引搜索流程

用户搜索“华为手机” --> 分词 --> 得到“华为”和“手机”两个词条 --> 去词条列表查询文档 id --> 得到每个词条所在文档 id（华为: 2, 3；手机: 1, 2） --> 根据文档 id 查询正向索引 --> 得到 id 为 1, 2, 3 的文档 --> 存入结果集 --> 返回结果

💡 **速记**

【核心考点】

Elasticsearch 是基于倒排索引的分布式搜索引擎，支持水平扩展和 Restful 接口。

倒排索引的核心概念是文档（Document，即一条数据）和词条（Term，即分词后的词语）。

【高频逻辑链】

正向索引查询链路：根据 id 索引 --> 逐行获取数据 --> 判断条件是否匹配 --> 全表扫描，数据量大时性能灾难。

倒排索引查询链路：分词用户输入 --> 得到词条 --> 查询词条对应的文档 id --> 根据 id 回表查询文档 --> 避免全表扫描。

【关键避坑】

正向索引支持多字段索引和排序，但面对模糊查询（如 %手机%）时会退化为全表扫描。

倒排索引在模糊搜索和词条搜索时速度极快，但仅能对词条建立索引，无法直接根据字段进行排序。
