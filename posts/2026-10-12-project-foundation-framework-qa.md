## 1、分层架构设计

问：你们项目的分层架构是怎么设计的？为什么要这么分层？

答：我们项目严格遵循三层分层规范，从外到内是 Controller 层、Service 层、Mapper 层，下层为上层提供调用接口，上层只能调用下一层，禁止跨层访问。

这么分层的好处是代码解耦，每一层的职责单一，后续修改某一层的逻辑不会影响其他层的代码，比如后续要把 MySQL 换成其他数据库，只需要改 Mapper 层的代码，Service 和 Controller 层完全不用动，代码的可维护性、可扩展性都非常好。

## 2、MyBatis-Plus 逻辑删除实现

问：你项目里 MyBatis-Plus 的逻辑删除是怎么实现的？

答：我是在实体类中的 deleted 字段添加 @TableLogic 注解，配置完成后，MP 会自动把执行的 delete 语句转换为 UPDATE 语句把 deleted 字段更新为 1，执行 select 查询时自动在 WHERE 条件后拼接 deleted=0，过滤掉已经标记删除的记录，实现逻辑删除的效果，既不会物理删除丢失数据，也不会影响正常业务查询。

也可以在 application.yml 中全局配置了 MyBatis-Plus 的逻辑删除规则，指定 deleted=0 代表未删除，deleted=1 代表已删除。

## 3、避免 SQL 注入风险

问：你们项目里是怎么避免 SQL 注入风险的？

答：我们全程使用 MyBatisPlus 框架，所有参数传递都用 #{} 预编译的方式，禁止使用 ${} 直接拼接 SQL，从根源上避免了 SQL 注入。

同时团队新增了 MyBatis 的全局配置，拦截所有包含特殊拼接字符的 SQL 提交，代码评审时会专门检查 Mapper 层的参数写法，确保没有手动拼接 SQL 的违规操作，全链路把 SQL 注入的风险降到最低。

## 4、页面静态化的好处

问：为什么要用页面静态化？有什么好处？

答：商品详情页属于高访问、低变化的页面，如果每次用户访问都要查数据库、执行业务逻辑，会给数据库带来非常大的压力。

页面静态化就是提前把动态生成的商品详情页渲染成静态 HTML 文件存在服务器，用户访问的时候直接返回静态文件，不需要访问后端服务和数据库，响应速度快很多，性能提升非常明显，同时静态页也更利于搜索引擎 SEO 收录。

## 5、密码加密为什么用 BCrypt 不用 MD5

问：你们项目的密码为什么用 BCrypt 加密，不用 MD5？

答：因为 BCrypt 是带随机盐的慢哈希算法，每个用户的密码加密串里自带独立的随机盐，不需要单独存盐值，就算两个用户密码一样，加密出来的结果也不一样，能有效防止彩虹表撞库。

而且 BCrypt 的算力因子可以调节加密耗时，就算攻击者拿到加密串，暴力破解的成本也非常高，安全性比普通 MD5 高很多，适合存储用户密码这种高敏感信息。

【核心考点】

三层架构：Controller -> Service -> Mapper，上层只能调用下一层，禁止跨层访问，实现代码解耦。

MyBatis-Plus 逻辑删除：实体类 @TableLogic 注解，delete 转 update，select 自动拼接 deleted=0。

SQL 注入防范：使用 #{} 预编译，禁止 ${} 拼接，全局拦截特殊字符，代码评审检查 Mapper 层。

页面静态化：高访问低变化页面渲染为静态 HTML，减轻数据库压力，提升响应速度，利于 SEO。

密码加密：BCrypt 慢哈希算法，自带随机盐，防彩虹表撞库，安全性远高于 MD5。

【高频逻辑链】

分层架构价值：职责单一 -> 代码解耦 -> 修改某一层不影响其他层 -> 可维护性与可扩展性好。

SQL 注入防范链路：MyBatisPlus 框架 -> #{} 预编译 -> 禁止 ${} 拼接 -> 全局拦截特殊字符 -> 代码评审检查。

【关键避坑】

逻辑删除字段需配置全局规则（deleted=0 未删除，deleted=1 已删除），避免手动拼接条件造成遗漏。

密码加密不可逆，BCrypt 自带盐值，无需单独存储盐字段，但需注意算力因子设置需平衡安全与性能。
