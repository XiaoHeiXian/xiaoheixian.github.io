## 1.1 大模型原生能力局限与 AI 应用开发必要性

原生大语言模型是基于海量文本数据训练的生成式模型，具备强大的自然语言理解、文本生成、逻辑推理能力，但在实际工程落地中存在天然短板，也是大模型应用开发存在的核心原因。其核心局限主要分为五大类。

**1、知识时效性受限**：大模型的知识仅覆盖训练数据集截止时间，无法获取实时网络信息，无法解答最新行业资讯、实时数据、动态政策等问题，存在严重的知识滞后性。

**2、无外部工具调用能力**：原生模型仅能依赖自身参数知识完成推理，无法调用计算器、搜索引擎、数据库、文件解析等外部工具，无法完成复杂计算、数据查询、文件处理等实操任务。

**3、上下文与记忆能力缺失**：原生模型单次对话无长期记忆，多轮对话上下文管理混乱，无法留存用户个性化信息、历史对话数据，难以支撑持续、个性化的智能交互场景。

**4、输出可控性差、幻觉严重**：大模型易生成虚假、错误、无依据的内容，且输出格式不统一、逻辑不严谨，无法满足企业场景下精准、规范、可溯源的输出要求。

**5、无法适配私有化专属数据**：原生模型无法直接读取企业内部知识库、私有文档、业务数据，只能依赖通用公开知识，无法搭建企业专属 AI 应用。

正是基于以上局限，单纯调用大模型接口无法满足落地需求，必须通过专业化开发框架对模型能力进行增强、约束、编排和扩展，这也是 LangChain、LangGraph 等 AI 编排框架的核心价值。

## 1.2 AI 应用开发主流范式

当前工业界主流的大模型应用开发范式主要分为三类，分别适配不同复杂度的业务场景，也是本教材后续所有知识点的核心基础。

**第一种：提示工程范式（Prompt Engineering）**。这是最基础的开发范式，通过优化提示词模板、添加角色设定、规则约束、示例样本，引导大模型输出规范、精准的结果。该范式无需复杂组件编排，开发成本低，适用于简单问答、文本改写、内容总结等轻量化场景，是所有 AI 应用开发的基础能力。

**第二种：检索增强生成范式（RAG，Retrieval-Augmented Generation）**。核心原理是将私有文档、业务数据进行向量化存储，用户提问时先检索相关专属知识，再将检索结果与用户问题拼接送入大模型，让模型基于私有真实数据作答。该范式解决了大模型知识滞后、私有数据适配、幻觉问题，是企业知识库、智能问答系统的核心落地会方案。

**第三种：智能体编排范式（Agent Orchestration）**。针对复杂多步骤任务，通过框架编排实现任务拆解、工具调用、循环推理、自我纠错、状态留存，让 AI 具备自主决策、自主执行、迭代优化的能力。该范式适用于自动化办公、科研辅助、多步骤业务处理等复杂场景，也是 LangGraph 的核心应用场景。

## 1.3 LangChain v1 版本重大架构革新、核心定位与生态升级

LangChain 是目前全球最主流的大模型应用开发开源框架，专注于大模型应用组件化、流水线编排、快速落地。相较于旧版本，LangChain v1.x 系列完成了颠覆性架构重构，彻底优化了旧版 API 冗余、逻辑混乱、兼容性差的问题，成为工业界标准化开发方案。

LangChain v1 版本核心架构革新主要包含四点。

1、**标准化智能体 API 重构**：废弃旧版杂乱的 ReAct Agent、OpenAI Agent 等多套冗余接口，统一推出 create_agent 极简标准化接口，实现全模型厂商统一适配，代码更简洁、可移植性更强。

2、**原生中间件机制落地**：v1 版本新增标准化中间件体系，支持工具调用拦截、请求预处理、输出后处理、权限校验、异常兜底等自定义逻辑，极大提升了应用的安全性和可扩展性，适配生产级开发需求。

3、**全模型统一适配协议**：新版本统一了 OpenAI、Anthropic、谷歌、通义千问、本地 Ollama 开源模型、Azure、AWS 等数十种大模型的调用接口，开发者可一键切换模型，无需大幅修改业务代码。

4、**深度绑定 LangGraph 底层架构**：LangChain v1 版本所有智能体底层均基于 LangGraph 驱动，自带状态管理、断点续跑、人机交互能力，彻底打通了基础组件与复杂工作流的技术壁垒。

LangChain 的核心定位是轻量化、高灵活、组件化的 AI 应用开发框架，主打快速搭建标准化 RAG、基础智能体、线性 AI 流水线，适合绝大多数轻量化、标准化企业 AI 应用落地。

## 1.4 LangGraph v1 核心优势及与 LangChain 的深度协同关系

LangGraph 是 LangChain 官方推出的状态化图编排框架，专门弥补 LangChain 线性流水线的能力短板，专注于复杂、循环、多分支、有状态的 AI 工作流与智能体系统开发。在 v1.x 版本生态中，二者不再是独立框架，而是基础组件+高级编排的深度协同体系。

LangGraph v1 版本核心优势体现在四个维度：状态持久化、流程可循环、人机可交互、高容错可回溯。不同于 LangChain 线性、一次性、无记忆的流水线执行逻辑，LangGraph 以状态（State）、节点（Node）、边（Edge）为核心，支持自定义工作流拓扑结构，可实现任务循环迭代、条件分支跳转、流程暂停干预、历史状态回溯、断点续跑等高级能力。

二者的协同关系是 v1 版本生态的核心重点：LangChain 负责基础组件封装与轻量化流水线搭建，LangGraph 负责复杂智能体与状态化工作流编排。LangChain 的模型调用、工具、提示词、RAG 组件可直接复用在 LangGraph 节点中，而 LangGraph 为 LangChain 智能体提供底层调度、状态管理和复杂流程支撑，二者结合可覆盖从简单问答到复杂多智能体系统的全场景开发需求。

## 1.5 新版框架核心能力解析

基于 LangChain+LangGraph v1.x 的新版技术生态，核心能力可归纳为四大标准化能力，也是本教材的核心教学内容。

1、**全场景模型适配能力**。统一接口适配闭源商用模型、开源本地模型、多模态模型，支持模型快速切换与兼容部署。

2、**组件化快速编排能力**。通过 LCEL 语法实现组件自由组合，快速搭建 RAG、工具调用、问答流水线等标准化应用。

3、**可定制智能体能力**。基于标准化 create_agent 接口+中间件机制，可按需定制决策逻辑、工具权限、输出规则的个性化智能体。

4、**状态化复杂工作流能力**。基于 LangGraph 实现循环推理、自我反思、人工干预、多智能体协作的高级 AI 系统。

## 1.6 新版调试观测工具：LangSmith 全链路追踪

LangSmith 是 LangChain 官方配套的可视化调试、监控、追踪工具，v1.x 版本框架默认深度适配，是生产级开发必备工具。不同于传统日志打印，LangSmith 可实现 AI 应用全链路可视化追踪，精准定位模型调用耗时、工具调用流程、状态变更、报错节点、检索精度问题。

LangSmith 核心能力包含：全流程可视化、接口耗时监控、报错自动定位、对话日志留存、性能指标统计、自动化评估、问题智能诊断修复。开发者仅需配置环境变量即可开启追踪功能，无需额外复杂开发。

### 1、LangSmith 核心功能

LangSmith 主要有四大核心能力，覆盖了 LLM 应用从开发到上线的全过程：

（1）**可观测性 (Observability)**：自动捕获 LLM 应用运行的每一步，形成详细的“追踪” (Trace)，方便调试和监控。

（2）**评估 (Evaluation)**：提供数据集和评估器，用于自动化测试应用性能，对比不同版本。

（3）**提示工程 (Prompt Engineering)**：提供一个“提示词中心” (Prompt Hub) 和在线“游乐场” (Playground)，用于创建、版本控制和迭代提示词。

（4）**生产监控 (Production Monitoring)**：上线后持续监控应用表现，通过仪表盘查看错误率、成本等关键指标。

### 2、快速上手：5 步开始使用

**第 1 步：注册账号并获取 API 密钥**

（1）访问 smith.langchain.com 注册账号。

（2）进入 Settings -> API Keys，点击 Create API Key 生成密钥。

**第 2 步：安装并配置环境**

在你的项目中安装 LangSmith SDK 并设置环境变量。

（1）安装 SDK：

    pip install -U langsmith

设置环境变量：在项目配置中设置以下变量：

    # langsmith

    LANGSMITH_TRACING=true

    LANGSMITH_ENDPOINT=https://api.smith.langchain.com

    LANGSMITH_API_KEY=sk-你的key

    LANGSMITH_PROJECT=项目名称

**第 3 步：为应用添加追踪 (Tracing)**

配置好环境后，LangSmith 就能自动追踪你的应用了。如果你使用 LangChain 或 LangGraph：只需设置好环境变量，追踪功能就会自动启用。

**第 4 步：在 UI 中查看追踪**

运行你的应用后，登录 LangSmith 网页端，在 Observability / Traces 页面就能看到每次运行的详细追踪记录，包括输入、输出、耗时和令牌使用量等。

**第 5 步：迭代提示与评估**

利用 LangSmith 的 UI 来优化你的应用：

- 提示词迭代：在左侧菜单进入 Prompts，点击 + Prompt 创建提示词。你可以在 Playground 中测试不同模型和参数配置。
- 创建评估：导航到 Datasets & Testing 部分，创建数据集和评估器，对你的应用进行自动化测试。

### 3、高级功能与最佳实践

掌握基础后，可以探索 LangSmith 的高级特性：

（1）**人工反馈闭环**：通过 Annotation Queues 收集人工反馈，对模型输出进行评分和标注。

## 💡 **速记**

【核心考点】

LangChain v1.x 的架构革新：废弃旧版冗余接口，统一 `create_agent`；引入中间件机制；统一全模型适配协议；底层深度绑定 LangGraph。

LangGraph 的定位：弥补 LangChain 无法处理复杂循环、分支的短板，以状态 (State)、节点 (Node)、边 (Edge) 为核心，支持状态持久化和断点续跑。

LangSmith 的作用：生产级 AI 应用必备，提供全链路追踪 (Tracing)、自动化评估 (Evaluation) 和提示词管理。

【高频逻辑链】

AI 应用范式演进：提示工程 (轻量) -> RAG (私有知识) -> Agent 编排 (复杂多步)。

LangChain 生态协同：LangChain 负责基础组件 (模型、RAG、工具) -> LangGraph 负责底层状态编排 -> LangSmith 负责全链路监控与调优。

【关键避坑】

环境变量是开启 LangSmith 追踪的关键，如果发现控制台没有数据，务必检查 `LANGSMITH_TRACING=true` 是否已正确设置且生效。

LangGraph 虽然强大，但如果是简单的线性任务（如单次问答），使用 LangChain 的 LCEL 或简单 Chain 即可，无需强行使用 LangGraph 增加系统复杂度。
